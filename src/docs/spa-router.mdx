Visage includes a fine-grained, zero-overhead Single Page Application (SPA) router (`@epoch32/visage/router` or exported from `@epoch32/visage`). It synchronizes browser URL history with reactive signals, eliminating whole-page reloads and bulky external routing dependencies.

<FeatureGrid>
  <FeatureCard icon="globe" title="HTML5 History Mode">
    Full <code>pushState</code> and <code>popstate</code> synchronization. Direct URL paths (e.g. <code>/signals</code> or <code>/docs/signals</code>) resolve cleanly without messy <code>#hash</code> workarounds.
  </FeatureCard>

  <FeatureCard icon="zap" title="Signal-Driven Matching">
    <code>useLocation()</code> and <code>useParams()</code> expose reactive signals that update point-to-point without re-evaluating unchanged parent component trees.
  </FeatureCard>
</FeatureGrid>

<Callout type="tip" title="Looking for File-Based MPAs?">
  If you are building content sites, marketing pages, or documentation using file-system routing and build-time static site generation (SSG), check out the [Opinionated MPA Pages Router](/mpa-pages).
</Callout>

## Basic Setup (&lt;Router&gt; & &lt;Routes&gt;)

Wrap your application in `<Router>` (defaults to `mode="history"`):

<CodeBlock
  filename="src/main.tsx"
  lang="tsx"
  code={`import { render, Router, Routes, Route, Link, useParams } from "@epoch32/visage";

function HomePage() {
  return <h1>Welcome to Visage</h1>;
}

function DocPage() {
  const params = useParams<{ slug: string }>();
  return <h1>Viewing Doc: {() => params().slug}</h1>;
}

function App() {
  return (
    <Router mode="history">
      {() => (
        <div class="app-layout">
          <nav>
            <Link href="/" class="nav-link">Home</Link>
            <Link href="/docs/signals" class="nav-link">Signals</Link>
          </nav>

          <Routes fallback={<div>Page Not Found (404)</div>}>
            <Route path="/" component={HomePage} />
            <Route path="/docs/:slug" component={DocPage} />
          </Routes>
        </div>
      )}
    </Router>
  );
}

render(() => <App />, document.getElementById("app")!);`}
/>

## Deferred Scope Mounts

In Visage's fine-grained execution model, components inside a Context Provider (like `<Router>`) should be passed as a child function:

<CodeBlock
  filename="scope-pattern.tsx"
  lang="tsx"
  code={`// Recommended: Evaluates DocsApp inside the active RouterContext scope
<Router mode="history">
  {() => <DocsApp />}
</Router>`}
/>

Passing `{() => <DocsApp />}` ensures `DocsApp` executes inside `runInScope` after `RouterContext` has been registered in the scope hierarchy, allowing hooks like `useLocation()` and `useNavigate()` to find the router instance immediately.

## Client Navigation (&lt;Link&gt;)

The `<Link>` component renders an accessible `<a>` tag with automatic `e.preventDefault()` and client-side history navigation:

<CodeBlock

export function HeaderNav() {

/>

## Class & Active State Preservation

Visage's `<Link>` accepts either `class` or `className` and seamlessly preserves base styles alongside the dynamic `activeClass`:

<CodeBlock
  filename="class-support.tsx"
  lang="tsx"
  code={`// Both class and className are fully supported:
<Link href="/signals" class="header-nav-link" activeClass="is-active">
  Signals
</Link>

<Link href="/store" className="header-nav-link">
  Store
</Link>`}
/>

When a route is active (matching `href`), `activeClass` (defaults to `"active"`) is appended to your base class. When inactive, your base class remains intact, preventing links from accidentally dropping their styling or reverting to browser default blue unstyled links.

## Native View Transitions API

Visage features first-class integration with the browser's native **View Transitions API** (`document.startViewTransition()`). It enables smooth, GPU-accelerated page transitions without bloated external animation frameworks.

<Callout type="experimental" title="Progressive Enhancement" tag="Browser Feature">
  The document View Transitions API (<code>document.startViewTransition</code>) is progressively enhanced. In browsers where the API is unavailable, Visage automatically falls back to synchronous DOM updates without throwing runtime errors or disrupting navigation.
</Callout>

### Router-Level View Transitions

Enable view transitions globally on the `<Router>`:

<CodeBlock
  filename="App.tsx"
  lang="tsx"
  code={`import { Router, Routes, Route, Link } from "@epoch32/visage";

function App() {
  return (
    <Router viewTransitions={true}>
      {() => (
        <div class="app">
          <Routes>
            <Route path="/" component={Home} />
            <Route path="/about" component={About} />
          </Routes>
        </div>
      )}
    </Router>
  );
}`}
/>

### Per-Link & Imperative Control

You can enable or override view transitions on individual `<Link>` components or via `useNavigate()`:

<CodeBlock
  filename="ViewTransitionExample.tsx"
  lang="tsx"
  code={`import { Link, useNavigate } from "@epoch32/visage";

export function Navigation() {
  const navigate = useNavigate();

  return (
    <nav>
      {/* Enable transition for this specific link */}
      <Link href="/gallery" viewTransition={true}>
        Photo Gallery
      </Link>

      {/* Imperative navigation with View Transition */}
      <button onClick={() => navigate("/dashboard", { viewTransition: true })}>
        Go to Dashboard
      </button>
    </nav>
  );
}`}
/>

If the user's browser does not yet support `document.startViewTransition`, Visage gracefully falls back to synchronous DOM updates with zero overhead or runtime exceptions.

## Speculative Prefetching (Speculation Rules)

Visage leverages modern browser **Speculation Rules API** (`<script type="speculationrules">`) to initiate next-page loading before the user even clicks, achieving instant 0ms perceived navigation.

<Callout type="experimental" title="Emerging Web Standard" tag="Speculation Rules">
  The W3C Speculation Rules API is supported in modern Chromium browsers (Chrome 109+, Edge 109+). In Safari and Firefox, Visage gracefully falls back to injecting standard <code>&lt;link rel="prefetch"&gt;</code> elements into the document head.
</Callout>

### Automatic Hover & Render Prefetching

Configure `<Link>` to prefetch speculatively:

<CodeBlock
  filename="PrefetchLink.tsx"
  lang="tsx"
  code={`import { Link, Router } from "@epoch32/visage";

// 1. Prefetch on pointer hover and keyboard focus:
<Link href="/docs/signals" prefetch="hover">
  Signals Guide
</Link>

// 2. Prefetch immediately upon element mount:
<Link href="/critical-dashboard" prefetch="render">
  Dashboard
</Link>

// 3. Cascade default prefetch behavior across all links in the router:
<Router prefetch="hover">
  {() => <AppNav />}
</Router>`}
/>

### Imperative Prefetching

Prefetch URLs programmatically via `usePrefetch()` or the standalone `prefetch()` helper:

<CodeBlock
  filename="imperative-prefetch.ts"
  lang="ts"
  code={`import { prefetch, usePrefetch } from "@epoch32/visage";

// Standalone function (useful in loaders or background tasks):
prefetch("/api/docs-chunk");

// Inside components via hook:
function RecommendedCard({ url }: { url: string }) {
  const prefetchUrl = usePrefetch();

  return (
    <div onMouseEnter={() => prefetchUrl(url)}>
      Card Content
    </div>
  );
}`}
/>

Visage automatically deduplicates prefetched URLs to prevent duplicate network requests and excludes mutating or non-navigable protocols (`javascript:`, `mailto:`, `tel:`, `#`). In browsers without Speculation Rules support, it seamlessly falls back to standard `<link rel="prefetch">`.

## Router Hooks

Visage exports fine-grained reactive hooks for URL inspection, prefetching, and navigation:

### useLocation()

Returns reactive signals for the current URL components:
- `location.pathname()`: Current path (e.g. `"/signals"`).
- `location.search()`: Query string (e.g. `"?page=2"`).
- `location.hash()`: Hash fragment (e.g. `"#overview"`).

### useNavigate()

Imperative navigation function for event handlers:

<CodeBlock
  filename="navigate-usage.ts"
  lang="ts"
  code={`import { useNavigate } from "@epoch32/visage";

function LoginForm() {
  const navigate = useNavigate();

  const handleLogin = async () => {
    await api.login();
    // Navigate with pushState:
    navigate("/dashboard");

    // Replace history entry with View Transition:
    // navigate("/dashboard", { replace: true, viewTransition: true });
  };

  return <button onClick={handleLogin}>Log In</button>;
}`}
/>

### useParams()

Returns a reactive accessor for dynamic URL pattern parameters:

<CodeBlock
  filename="params-usage.ts"
  lang="ts"
  code={`import { useParams } from "@epoch32/visage";

// For route path="/users/:id":
const params = useParams<{ id: string }>();
console.log(params().id); // Reactive accessor`}
/>

### usePrefetch()

Returns a function to speculatively prefetch URLs:

<CodeBlock
  filename="use-prefetch.ts"
  lang="ts"
  code={`import { usePrefetch } from "@epoch32/visage";

const prefetch = usePrefetch();
prefetch("/docs/quickstart");`}
/>
