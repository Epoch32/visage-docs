Side effects allow your application to escape pure reactive computations and synchronize state with the outside world. An effect automatically tracks every signal read during its execution, runs immediately upon creation, and re-executes whenever those signals update.

<FeatureGrid>
  <FeatureCard icon="zap" title="Eager & Push-Based">
    Unlike <code>computed</code> which is lazy and only evaluates when read, an <code>effect</code> is eager. It queues in pending effects and flushes automatically to execute side-effects like DOM updates, network requests, or timers.
  </FeatureCard>

  <FeatureCard icon="trash" title="Self-Cleaning Lifecycle">
    Effects automatically execute their registered cleanups before each re-run and when their enclosing component scope disposes, preventing memory leaks and dangling event listeners.
  </FeatureCard>
</FeatureGrid>

## Computed vs Effect: When to Use Which?

Both `computed` and `effect` track reactive dependencies, but they serve completely different purposes:

## Why Use an Effect Over a Computed?

You use an `effect` instead of a `computed` whenever you need to **interact with the outside world** rather than simply calculate a derived value.

Because Visage computeds use **dirty loading**, if nothing in your application is actively reading a computed value, it will **never run**. If you place side effects like network requests or analytics inside a `computed`, they will silently fail to fire. An `effect` runs eagerly whenever its dependencies change:

<CodeBlock
  filename="effect-use-cases.ts"
  lang="ts"
  code={`import { createSignal, effect } from "@epoch32/visage";

const [unreadCount, setUnreadCount] = createSignal(3);
const [room, setRoom] = createSignal("general");

// 1. Imperative Browser API synchronization
effect(() => {
  document.title = unreadCount() > 0 
    ? \`(\${unreadCount()}) Messages\` 
    : "Messages";
});

// 2. External socket / streaming connection with cleanup
effect(() => {
  const socket = new WebSocket(\`wss://api.example.com/chat/\${room()}\`);
  socket.onmessage = (event) => console.log("Received:", event.data);

  return () => {
    socket.close();
  };
});`}
/>

<Callout type="tip" title="The Rule of Thumb">
  <ul style={{ paddingLeft: "18px", marginTop: "4px" }}>
    <li><strong>Do I need a value to display, compute, or pass around?</strong> Use <code>computed</code>.</li>
    <li><strong>Do I need to trigger an action or update an external system?</strong> Use <code>effect</code>.</li>
  </ul>
</Callout>

## Cleanups & Lifecycle

Effects frequently set up asynchronous operations like event listeners, intervals, WebSockets, or third-party canvas instances. Visage gives you two equivalent ways to register teardown logic:

<CodeBlock
  filename="cleanup-patterns.ts"
  lang="ts"
  code={`import { createSignal, effect, onCleanup } from "@epoch32/visage";

const [userId, setUserId] = createSignal(1);

// Pattern 1: Return a cleanup function directly
effect(() => {
  const socket = new WebSocket(\`wss://api.example.com/users/\${userId()}\`);
  
  // Returned callback runs before next run and on unmount:
  return () => {
    socket.close();
  };
});

// Pattern 2: Call onCleanup() anywhere inside the effect or scope
effect(() => {
  const handler = (e: MouseEvent) => console.log(e.clientX);
  window.addEventListener("mousemove", handler);

  onCleanup(() => {
    window.removeEventListener("mousemove", handler);
  });
});`}
/>

## Batching & Execution Order

When multiple signals change together inside a batch, Visage avoids redundant effect executions. Effects are added to a pending set and only flush once the batch depth returns to zero:

<CodeBlock
  filename="batching.ts"
  lang="ts"
  code={`import { createSignal, effect, batch } from "@epoch32/visage";

const [first, setFirst] = createSignal("Ada");
const [last, setLast] = createSignal("Lovelace");

effect(() => {
  console.log("Full Name:", first(), last());
});
// Logs once initially: "Full Name: Ada Lovelace"

// Without batch():
// setFirst("Grace"); -> effect runs!
// setLast("Hopper"); -> effect runs again!

// With batch():
batch(() => {
  setFirst("Grace");
  setLast("Hopper");
});
// Logs only ONCE at the end of the batch: "Full Name: Grace Hopper"`}
/>

## Infinite Loops & Common Traps

<Callout type="warning" title="Trap 1: Writing to Read Signals">
  If an effect reads a signal and also writes to that same signal, it will trigger itself in an infinite loop! Visage includes built-in cycle detection to safeguard your app, but you should avoid writing to tracked dependencies inside an effect. Use <code>untrack()</code> if you need to read a signal's value without subscribing to it.
</Callout>

<Callout type="warning" title="Trap 2: Using Effect for Derived State">
  Never use an <code>effect</code> to calculate a value and store it in another signal. That causes unnecessary double renders and timing glitches. Always use <code>computed(() =&gt; ...)</code> for derived state!
</Callout>

## API Reference

### `effect()`

Creates an eager reactive side-effect runner. Runs immediately and subscribes to all signals accessed during execution. Re-executes automatically when those dependencies change.

<CodeBlock
  lang="ts"
  filename="signature"
  code={`function effect(fn: () => void | CleanupFn): CleanupFn`}
/>

#### Parameters
- `fn` (`() => void | CleanupFn`): The side-effect callback. May optionally return a cleanup function to teardown resources before re-execution or unmount.

#### Returns
- `CleanupFn`: A manual disposal function `() => void` that stops the effect and tears down all registered cleanups and subscriptions.

<hr className="api-divider" />

### `onCleanup()`

Registers a teardown callback for the currently executing effect or active component scope. Runs right before the effect re-runs or when the scope is destroyed.

<CodeBlock
  lang="ts"
  filename="signature"
  code={`function onCleanup(fn: CleanupFn): void`}
/>

#### Parameters
- `fn` (`() => void`): The cleanup function to execute on teardown.

<hr className="api-divider" />

### `createEffect()`

A drop-in, Solid-compatible alias for `effect`. Identical in behavior and signature.

<CodeBlock
  lang="ts"
  filename="signature"
  code={`function createEffect(fn: () => void | CleanupFn): CleanupFn`}
/>
