Signals are the atomic reactive building blocks in Visage. Unlike frameworks that rely on Virtual DOM diffing and re-running entire component trees, Visage components execute **exactly once**. Signals establish direct point-to-point connections to the precise DOM text nodes and attributes they control.

<FeatureGrid>
  <FeatureCard icon="zap" title="Microsecond Micro-Updates">
    Calling a signal setter updates only subscribed DOM text nodes directly, skipping whole-tree diffs, fiber reconciliation, and garbage collector pressure.
  </FeatureCard>

  <FeatureCard icon="gauge" title="Glitch-Free Execution">
    Visage tracks topological dependencies using a synchronous, deterministic push/pull algorithm that prevents intermediate inconsistent state across computed graphs.
  </FeatureCard>
</FeatureGrid>


## Anatomy & Syntax

The `createSignal` function returns a 2-element tuple: a **getter accessor** and a **setter function**:

<CodeBlock
  filename="signals-basic.ts"
  lang="ts"
  code={`import { createSignal } from "@epoch32/visage";

// 1. Declare the signal with an initial value
const [count, setCount] = createSignal<number>(0);

// 2. Read the signal by invoking it as a function
console.log(count()); // -> 0

// 3. Update the signal by calling the setter
setCount(10);
console.log(count()); // -> 10`}
/>

<Callout type="tip" title="Visage Pro-Tip: JSX Auto-Unwrapping">
  In Visage JSX, you can interpolate either <code>&#123;count&#125;</code> or <code>&#123;count()&#125;</code>. Both subscribe automatically to fine-grained updates, but passing <code>&#123;count&#125;</code> directly passes the accessor function without allocating an unnecessary wrapper closure.
</Callout>

## Functional Updates

When your next state depends on the previous state, pass an updater callback to avoid race conditions or stale closures:

<CodeBlock
  filename="functional-update.ts"
  lang="ts"
  code={`const [count, setCount] = createSignal(1);

// Pass a callback taking the previous value:
setCount(prev => prev * 2); // count is now 2
setCount(prev => prev * 2); // count is now 4`}
/>

## Equality & Deduplication

By default, Visage uses `Object.is` equality to prevent redundant downstream notifications. If you set the same value, no DOM updates fire. You can customize equality checks in options:

<CodeBlock
  filename="custom-equality.ts"
  lang="ts"
  code={`// Always trigger subscribers, even on identical values:
const [pulse, setPulse] = createSignal(0, { equals: false });

// Or specify custom comparison logic:
const [coords, setCoords] = createSignal(
  { x: 0, y: 0 },
  { equals: (a, b) => a.x === b.x && a.y === b.y }
);`}
/>

## Common Traps to Avoid

<Callout type="warning" title="Trap 1: Destructuring Props">
  Because components execute only once, destructuring incoming props like <code>const &#123; value &#125; = props;</code> strips reactivity! Always access reactive properties on props as functions or properties (e.g., <code>props.value</code>).
</Callout>

<Callout type="warning" title="Trap 2: Reading Outside Reactive Scopes">
  Reading <code>count()</code> in the outer body of a component function only executes once during mount. If you want derived calculations that update dynamically when <code>count</code> changes, use <code>computed(() =&gt; count() * 2)</code> or wrap the expression in an accessor function <code>&#123;() =&gt; count() * 2&#125;</code>.
</Callout>

## API Reference

### `createSignal()`

Creates an atomic reactive state signal container. Returns a 2-tuple containing a read-only getter accessor and a state setter function.

<CodeBlock
  lang="ts"
  filename="signature"
  code={`function createSignal<T>(
  initialValue: T,
  options?: SignalOptions<T>
): [Accessor<T>, Setter<T>]`}
/>

#### Parameters
- `initialValue` (`T`): The initial value assigned to the signal upon creation.
- `options.equals` (`false | ((prev: T, next: T) => boolean)`, *optional*): Custom equality comparator function. Pass `false` to bypass equality checks and always trigger downstream reactions. Defaults to `Object.is`.
- `options.persist` (`string`, *optional*): Storage key to automatically persist and rehydrate this signal's value in `localStorage` across reloads.

#### Returns
- `[Accessor<T>, Setter<T>]`: A 2-tuple where index `0` is the getter accessor function `() => T`, and index `1` is the setter function `(value: T | ((prev: T) => T)) => void`.

<hr className="api-divider" />

### `untrack()`

Executes a block of code without registering dynamic reactive subscriptions to any signals read inside it. Useful when reading a signal's value inside an effect or computed without re-triggering when that signal updates.

<CodeBlock
  lang="ts"
  filename="signature"
  code={`function untrack<T>(fn: () => T): T`}
/>

#### Parameters
- `fn` (`() => T`): Function to execute in an untracked reactive execution scope.

#### Returns
- `T`: The synchronous return value of `fn()`.
