## Atomic Updates with batch()

When you update multiple signals that share downstream subscribers, updating them sequentially without batching causes those subscribers to execute multiple times. In complex graphs, this can lead to temporary invalid states (known as *glitches*):

<CodeBlock
  filename="batch-example.ts"
  lang="ts"
  code={`import { createSignal, effect, batch } from "@epoch32/visage";

const [width, setWidth] = createSignal(10);
const [height, setHeight] = createSignal(20);

// Subscriber observing both:
effect(() => {
  console.log("Area:", width() * height());
});

// Without batch():
// setWidth(30);  -> logs Area: 600
// setHeight(40); -> logs Area: 1200 (executed twice!)

// With batch():
batch(() => {
  setWidth(30);
  setHeight(40);
});
// Logs Area: 1200 exactly ONCE at the end of the batch!`}
/>

## Reactive Scopes & Automatic Memory Cleanup

In long-running client applications, event listeners and reactive computations can easily create memory leaks if not properly destroyed. Visage organizes reactivity into a tree of `Scope` instances:

- **Parent-Child Ownership:** When an effect or component creates child computeds or effects, those children belong to the parent scope.
- **Cascading Disposal:** When a scope disposes (e.g., when a component unmounts or a `<Show>` branch hides), it recursively disposes all child scopes and executes every registered `onCleanup` callback.
- **Zero Lingering Listeners:** All signal subscriptions are pruned from dependencies, leaving zero memory footprint.

## Isolated Roots with createRoot()

Sometimes you want to create a reactive computation that lives outside of any component lifecycle, such as a global state manager, a service worker bridge, or a plugin. Use `createRoot` to create an isolated scope that outlives current execution:

<CodeBlock
  filename="create-root.ts"
  lang="ts"
  code={`import { createRoot, createSignal, effect } from "@epoch32/visage";

// Create an isolated reactive root:
const dispose = createRoot((dispose) => {
  const [count, setCount] = createSignal(0);

  effect(() => {
    console.log("Global counter:", count());
  });

  // Return the manual disposal handle
  return dispose;
});

// Later, when you want to teardown this entire reactive universe:
dispose();`}
/>

## Reading Without Tracking (untrack)

If you need to read a signal's value inside an effect or computed without making that calculation re-run when the signal changes, wrap the read in `untrack()`:

<CodeBlock
  filename="untrack.ts"
  lang="ts"
  code={`import { createSignal, effect, untrack } from "@epoch32/visage";

const [pageId, setPageId] = createSignal("home");
const [analyticsId, setAnalyticsId] = createSignal(101);

effect(() => {
  // pageId() IS tracked: effect re-runs when pageId changes
  const page = pageId();

  // analyticsId() is NOT tracked: changing it will not trigger this effect
  const user = untrack(() => analyticsId());

  console.log(\`Logging view for page \${page} by user \${user}\`);
});`}
/>
