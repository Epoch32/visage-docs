## Vite Configuration (vite.config.ts)

Add `visage()` and `visageLucide()` to your Vite plugin array:

<CodeBlock
  filename="vite.config.ts"
  lang="ts"
  code={`import { defineConfig } from "vite";
import visage, { visageLucide } from "@epoch32/visage/vite";

export default defineConfig({
  plugins: [
    visage({
      devtools: true, // Auto-inject in dev mode
      hmr: true,      // Fast state-preserving HMR
    }),
    visageLucide(),   // Native Lucide SVG icon support
  ],
});`}
/>

## Signal-Preserving HMR

In traditional frameworks, HMR often resets component state back to defaults. Visage's Vite plugin injects fine-grained HMR boundaries that replace component factory functions while keeping signal store instances alive:

## Lucide Icon Transform (visageLucide)

Many existing libraries and icon sets target React. Visage's `visageLucide()` plugin intercepts imports from `lucide-react` at compile time and transforms them into native Visage SVG elements:

<CodeBlock
  filename="IconUsage.tsx"
  lang="tsx"
  code={`// Zero react dependency! Transformed automatically to native Visage SVG:
import { Check, Heart, Sparkles, Terminal } from "lucide-react";

export function IconBar() {
  return (
    <div>
      <Sparkles size={18} color="var(--pink-500)" />
      <Terminal size={18} />
      <Heart size={18} />
    </div>
  );
}`}
/>

## Full-Stack Dev Server RPC

You can attach your server's RPC router directly into the Vite development server so frontend API calls work without running a separate backend server:

<CodeBlock
  filename="vite.config.ts"
  lang="ts"
  code={`import { defineConfig } from "vite";
import visage from "@epoch32/visage/vite";
import { appRouter } from "./server/router";

export default defineConfig({
  plugins: [
    visage({
      rpc: {
        router: appRouter,
        endpoint: "/api/rpc",
      },
    }),
  ],
});`}
/>

Now, client requests to `/api/rpc` are handled directly by your typed server procedures inside Vite!

## Package Deduplication

If you have multiple dependencies in a monorepo or nested `node_modules` that depend on `@epoch32/visage`, the Vite plugin automatically aliases `@epoch32/visage` to a single root instance. This ensures that signals, contexts, and batch queues share one single reactive engine instance.
